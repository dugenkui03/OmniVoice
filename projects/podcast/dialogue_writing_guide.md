# Podcast Dialogue Writing Guide

这份文档记录“甄嬛版播客”台词的写作规则。目标不是写旁白，也不是写角色独白，而是写三个人坐在一起聊天的播客对话：他们保留剧中身份，但已经像下戏后坐到桌前复盘剧情，有问、有接、有笑、有梗。

## 适用目标

把一段剧集分析、角色信息、生词卡片，改写成可用于 OmniVoice TTS 的多角色中文播客脚本。

脚本应该像真实播客：

- 每句短，尽量一口气说完。
- 角色之间有来有回，不要连续长篇讲解。
- 有人提问，有人回应，有人补刀或接梗。
- 角色像“剧中人 + 置身事外的演员/嘉宾”的混合状态。
- 生词讲解要自然插进聊天，不要像课堂朗读。

## 输入数据

推荐输入这些数据：

- `episode_analysis.json`：剧集分析结果，至少包含：
  - `dialogue`：原剧台词，含 `speaker`、`text_zh`、`text_en`、时间戳。
  - `speakers`：角色列表和角色简介。
  - `vocab_cards`：英文单词、生词解释、例句、对应剧情台词。
- `characters.json`：角色与音色映射信息。
- `voice_references.json` 或角色音色规划：每个角色有哪些参考音频和情绪风格。
- 用户指定的播客风格：
  - 例如“戏中戏圆桌”“下戏后聊天”“有梗但不脱离剧情”。
- 输出长度要求：
  - 例如前 13 句试听、3 分钟、5 分钟、完整一期。

## 内容规则

### 对话优先

台词必须围绕对话展开。不要让每个角色轮流发表小作文。

推荐结构：

```text
周宁海：抛问题或串场。
华妃：反应、吐槽、追问。
曹贵人：解释、接梗、给出剧情逻辑。
周宁海：补刀或把梗翻译成现代说法。
```

好例子：

```text
周宁海：那曹贵人，你说恭喜娘娘的时候，真不怕娘娘当场翻脸？
华妃：我当时心里真想说，你是不是串台了？
曹贵人：怕呀。但不这么说，娘娘就只会继续骂我。
```

差例子：

```text
曹贵人：这一段主要表现了华妃失权后的愤怒，同时也说明了宫廷政治中证据的重要性。
```

### 句子长度

每句建议 `12-35` 个汉字左右，最多不要超过 `55` 个汉字。TTS 更容易把短句读成自然聊天。

一段播客不要只追求信息密度。宁可拆成三句：

```text
华妃：那你接下来怎么圆？
曹贵人：我圆的不是权，是证据。
周宁海：哦，题目被你换了。
```

不要写成一句：

```text
华妃问曹贵人接下来如何解释，曹贵人表示自己要改变讨论框架，周宁海总结她换了题目。
```

### 梗的使用

梗要围绕剧情和角色关系，不要为了搞笑脱离内容。

可用梗类型：

- 现代职场梗：汇报方案、管理员权限、开会、PPT。
- 播客现场梗：麦开了吗、收麦、主持费、坐下慢慢聊。
- 戏中戏梗：刚演完那场、戏里请罪戏外聊天、串台。
- 权力关系梗：群主、权限、证据链、旧情账户。

梗要短，像顺口接话：

```text
周宁海：[laughter] 曹贵人随身带方案，入宫自带 PPT。
```

不要把梗解释太长：

```text
周宁海：这就好比现代职场里一个员工带着完整 PPT 来汇报，她其实已经准备好了危机公关方案。
```

## 标签使用规则

### 只使用 OmniVoice 支持的标签

当前项目推荐只使用 README 中明确支持的标签：

```text
[laughter]
[sigh]
[confirmation-en]
[question-en]
[question-ah]
[question-oh]
[question-ei]
[question-yi]
[surprise-ah]
[surprise-oh]
[surprise-wa]
[surprise-yo]
[dissatisfaction-hnn]
```

不要直接照搬 ElevenLabs 的标签，例如 `[whisper]`、`[hesitant]`、`[angry]`、`[curious]`。这些不一定被 OmniVoice 当前模型正确理解。

### 标签密度

当前经验里，效果最好的是“少量关键标签”，不是每句都贴标签。

推荐：

- 大约 `1/4` 到 `1/3` 的台词带显式标签。
- 笑点、叹气、强烈不满、关键追问处加标签。
- 其他台词靠文本本身的口语节奏表达。

不推荐：

- 每句开头都加标签。
- 标签堆叠，例如 `[surprise-oh] [laughter]` 连着放。
- 为了加标签而改变台词意思。

### 笑声规则

笑声不要写成正文。TTS 文本里不要写“哈哈哈”“呵呵”“嘿嘿”这类拟声词，否则模型容易把它们当普通汉字硬读出来。

推荐用音频标签表达笑声：

```text
[laughter] 所以我先声明，戏里请罪，戏外聊天，不许再让我跪。
```

不推荐：

```text
[laughter] 哈哈哈，所以我先声明，戏里请罪，戏外聊天，不许再让我跪。
哈哈哈，曹贵人随身带方案，入宫自带 PPT。
```

如果后续切换到其他 TTS 引擎，且该引擎使用 `LAUGH`、`<LAUGH>` 或类似标签，可以在适配层把 `[laughter]` 映射过去；写作规则仍然是：**笑声用标签，不进正文**。

视频字幕可以单独显示“哈哈哈”作为氛围梗，但那应该放在视频 overlay 或字幕生成逻辑里，不要放进实际送入 TTS 的 `text`。

### 标签位置

优先放在句首，尤其是这一整句都需要同一种状态时：

```text
[dissatisfaction-hnn] 轻松？本宫刚演完那场，火气还没散呢。你们先别笑。
```

也可以少量放在自然转折处，但不要频繁使用：

```text
加盐？[laughter] 你是真会说话。怪不得戏里跪着，也像在开会。
```

不推荐把标签塞在每个小短语中间，会显得生硬。

### 情绪与发声方式

OmniVoice 当前可用标签里，“发声方式”不如 ElevenLabs 丰富。写台词时用两层策略：

- 用标签表达强事件：笑、叹气、疑问、惊讶、不满。
- 用文字节奏表达发声方式：小声、迟疑、停顿、转折。

例子：

```text
我小声问一句啊...曹贵人，你说恭喜娘娘的时候，真不怕娘娘当场翻脸？
嗯...都有一点。您那会儿像一锅刚开的水，我总不能一上来就加盐吧。
```

这里的“小声问一句”“嗯...”“...”比硬造 `[whisper]`、`[hesitant]` 更适合当前模型。

## 推荐脚本形态

结构化输出建议使用 JSON，方便 `generate_podcast.py` 后续读取或人工迁移。

```json
[
  {
    "line_id": "001",
    "part": "开场",
    "speaker": "周宁海",
    "reference_key": "taijian_notice",
    "emotion": "随手开麦",
    "text": "哎，麦开了吗？...开了哈。娘娘，曹贵人，今天不升堂，咱们就随便聊两句。",
    "duration_sec": 6.2,
    "pause_after_sec": 0.22
  }
]
```

字段说明：

- `line_id`：三位编号字符串，如 `001`。
- `part`：段落，如 `开场`、`剧情`、`生词`、`结尾`。
- `speaker`：说话人，必须能映射到角色音色。
- `reference_key`：音色参考 key，例如 `huafei_skeptical`、`cao_strategy`。
- `emotion`：给人看的表演说明，不一定传给模型。
- `text`：实际送入 TTS 的台词，可包含少量 OmniVoice 支持标签。
- `duration_sec`：期望语音时长。
- `pause_after_sec`：该句后停顿。

## 使用方式

1. 准备输入数据：剧集分析 JSON、角色列表、生词卡片、音色 key。
2. 用下方 Prompt 生成结构化台词。
3. 人工检查三点：
   - 是否真的在对话，而不是轮流讲解。
   - 梗是否围绕剧情，不突兀。
   - 标签是否少量关键使用。
4. 把生成结果迁移到 `generate_podcast.py` 的 `PODCAST_LINES`，或改造脚本读取 JSON。
5. 先跑试听：

```bash
uv run python projects/podcast/generate_podcast.py --max-lines 13 --run-name preview_13
```

6. 听完确认节奏，再跑完整版本：

```bash
uv run python projects/podcast/generate_podcast.py --run-name full_episode
```

## 可复用 Prompt

下面这段 Prompt 可以给其他模型使用，也可以直接给 Codex 使用。

```text
你是一个中文播客台词编剧，任务是把一段电视剧剧情分析、生词卡片和角色资料，改写成适合 OmniVoice TTS 生成的多角色播客脚本。

目标风格：
- 三个角色像下戏后坐到播客桌前聊天。
- 他们保留剧中身份，但也能置身事外地复盘刚演完的剧情。
- 整体是轻松、有梗、有来有回的“戏中戏圆桌”。
- 不要写成旁白、课堂讲解或角色独白。

输入数据：
1. 角色列表：包含 speaker、角色性格、可用 reference_key。
2. 剧情摘要：这一集发生了什么、关键冲突是什么。
3. 原始台词片段：可引用或改写成播客聊天。
4. 生词卡片：word、meaning_zh、original_sentence、explanation_zh。
5. 目标长度：例如前 13 句试听，或完整 5 分钟。

写作规则：
1. 台词必须是对话。每句都要像有人在接上一句，不要轮流发表长篇观点。
2. 每句尽量短，建议 12-35 个汉字，最长不超过 55 个汉字。
3. 多使用提问、回应、补刀、接梗、短暂停顿。
4. 梗必须来自剧情、角色关系或播客现场，例如：麦开了吗、收麦、PPT、管理员权限、群聊、方案汇报、串台、赐座。
5. 生词讲解要自然嵌入聊天，例如角色先说一个剧情梗，再顺手解释单词。
6. 不要使用过度现代、脱离角色的网络烂梗。

OmniVoice 标签规则：
1. 只能使用这些标签：
   [laughter], [sigh], [confirmation-en], [question-en], [question-ah], [question-oh], [question-ei], [question-yi], [surprise-ah], [surprise-oh], [surprise-wa], [surprise-yo], [dissatisfaction-hnn]
2. 标签不要太密。推荐大约 1/4 到 1/3 的台词带标签。
3. 优先在笑点、叹气、强烈不满、关键追问处加标签。
4. 标签通常放句首；少数情况下可放在自然转折处，例如“加盐？[laughter] 你是真会说话。”
5. 不要连续堆叠多个标签。
6. 不要使用 OmniVoice 不支持的标签，例如 [whisper]、[angry]、[curious]、[hesitant]。
7. 如果需要耳语、迟疑、停顿、转折，用文字表达：例如“我小声问一句啊...”“嗯...”“你等等...”，不要硬造标签。
8. 笑声必须用音频标签表达，不要把“哈哈哈”“呵呵”“嘿嘿”写进 TTS 正文。当前 OmniVoice 使用 [laughter]；如果目标引擎支持 LAUGH 或 <LAUGH>，由适配层映射，不改变正文规则。

输出格式：
请输出 JSON 数组。每个元素包含：
- line_id：三位编号字符串
- part：开场 / 剧情 / 生词 / 结尾
- speaker：说话人
- reference_key：角色音色 key
- emotion：给人看的表演说明
- text：实际 TTS 文本，可含少量 OmniVoice 支持标签
- duration_sec：建议时长，数字
- pause_after_sec：句后停顿，数字

质量自检：
输出前请检查：
1. 是否有明显的一问一答和互相接话？
2. 是否存在连续 3 句以上同一个人长篇讲解？如果有，请拆成对话。
3. 梗是否服务剧情？
4. 标签是否少量关键使用，而不是每句都加？
5. 有没有使用 OmniVoice 不支持的标签？如果有，请删除或改成文字描述。
6. 有没有把笑声写成“哈哈哈”等正文？如果有，请改成 [laughter] 或目标引擎的等价笑声标签。
```

## 前 13 句参考

这组是目前更推荐的写法：标签少，短句多，对话感强。

```text
周宁海：哎，麦开了吗？...开了哈。娘娘，曹贵人，今天不升堂，咱们就随便聊两句。
华妃：[dissatisfaction-hnn] 轻松？本宫刚演完那场，火气还没散呢。你们先别笑。
曹贵人：[laughter] 我先声明啊，戏里请罪，戏外聊天，不许再让我跪。
周宁海：行。那我先把茶放这儿。咱们从刚才那场开始，聊着聊着，再捡几个英文词。
华妃：曹贵人，我真想问你：你一进来那句夏日炎炎，到底是灭火，还是试探我？
曹贵人：嗯...都有一点。您那会儿像一锅刚开的水，我总不能一上来就加盐吧。
华妃：加盐？[laughter] 你是真会说话。怪不得戏里跪着，也像在开会。
周宁海：我在旁边听着都愣了。表面是请罪，实际像带着方案来汇报。
曹贵人：没办法呀...娘娘失了协理六宫之权，这不是小事。
华妃：是啊，协理六宫没了，差不多就是管理员权限被撤了。
周宁海：[laughter] 后宫群聊里，娘娘突然不能踢人了。
周宁海：我小声问一句啊...曹贵人，你说恭喜娘娘的时候，真不怕娘娘当场翻脸？
华妃：我当时心里真想说，你是不是串台了？但我忍住了。
```
